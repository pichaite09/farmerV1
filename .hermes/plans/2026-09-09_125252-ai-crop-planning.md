# AI Crop Planning Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** เพิ่มผู้ช่วย AI สร้างแผนปลูกพืชภาษาไทยจากข้อมูลฟาร์มจริง ให้เกษตรกรตรวจแก้และยืนยันก่อนสร้างรอบผลิต/ตารางงาน

**Architecture:** Flutter Web → authenticated FastAPI → context builder + validated agronomic templates + AI provider → validated draft in PostgreSQL. AI ไม่มีสิทธิ์เขียนตารางงานโดยตรง การนำแผนไปใช้เป็นธุรกรรมแยกที่ผู้ใช้ยืนยันและป้องกันรายการซ้ำ

**Tech Stack:** Flutter/Material 3 Green Field, FastAPI/Pydantic, PostgreSQL/SQLAlchemy/Alembic; AI ผ่าน server-side provider adapter ที่เลือกภายหลัง

## ประสบการณ์ใช้งานที่เสนอ
1. ปุ่ม “วางแผนปลูกด้วย AI” ในหน้ารอบผลิต ไม่เพิ่มแท็บที่ห้าให้เมนูมือถือแน่น
2. เลือกแปลง → เลือกพืช/พันธุ์/วิธีปลูก → วันเริ่ม/ช่วงเก็บเกี่ยว → น้ำ/ดิน/งบ/แรงงาน → ตรวจข้อมูลที่จะส่ง AI
3. แสดงข้อมูลเดิมที่นำมาใช้และช่องข้อมูลจำเป็นที่ยังขาด ผู้ใช้แก้ได้ก่อนส่ง
4. สร้างร่าง → หน้าสรุป + Timeline เตรียมดิน/ปลูก/ดูแล/ตรวจแปลง/เก็บเกี่ยว + งบประมาณเป็นช่วง + ความเสี่ยง/สมมติฐาน/แหล่งอ้างอิง
5. แก้วัน/งาน/งบ/หมายเหตุรายรายการ และบันทึกร่าง โดยไม่สร้างรายการใช้เงินจริง
6. กด “ยืนยันใช้แผน” → preview รายการที่จะสร้าง → ยืนยัน → สร้างรอบผลิตใหม่หรือผูกรอบเดิมที่เลือก + งานที่เลือก
7. ใช้ตารางงานเดิมเพื่อติดตาม งานเสร็จไม่หมายความว่าเกิดรายจ่ายหรือกิจกรรมจริงโดยอัตโนมัติ
8. AI ปรับร่างใหม่ได้เป็น revision แต่ห้ามทับงานที่ทำเสร็จหรือกำหนดการจริงโดยเงียบ

## Input และการคำนวณ
- จำเป็น: แปลงของผู้ใช้ พื้นที่พร้อมหน่วย พืช วิธีปลูก วันเริ่ม แหล่งน้ำ; พันธุ์ที่ไม่ทราบต้องระบุไม่ทราบ
- เพิ่มเติม: จังหวัด/อำเภอหรือพิกัดโดยยินยอม ชนิดดิน ผลตรวจดิน ประวัติปลูก งบ แรงงาน เครื่องจักร เป้าหมายวันเก็บเกี่ยว
- Backend คำนวณพื้นที่ วันที่ งบรวม และช่วงรายได้จากจำนวน/ราคาที่มีแหล่งที่มาด้วย Decimal ไม่เชื่อผลรวมจาก LLM
- ระบุ provenance ของตัวเลข: ผู้ใช้กรอก/ประวัติจริง/เอกสารอ้างอิง/สมมติฐาน พร้อมวันที่ข้อมูล
- ไม่สั่งอัตราปุ๋ยเฉพาะเจาะจงโดยไม่มีข้อมูลรองรับ ไม่ให้สูตรผสมสารเคมีหรืออัตราพ่นที่ไร้ฉลาก/แหล่งอนุมัติ ให้ปรึกษาเจ้าหน้าที่เกษตรในกรณีเสี่ยง

## Data model ที่เสนอ
- planting_plans: id, owner_user_id, plot_id, target_cycle_id nullable, status(draft/ready/applied/archived), current_revision, created_at, updated_at
- planting_plan_revisions: plan_id, revision, input_snapshot JSONB, result JSONB, schema_version, template_version, source_ids, model_id, prompt_version, generated_at; unique(plan_id, revision)
- planting_plan_items: plan_id, revision, stage, title, start/end_date, budget_min/max, explanation, selected, linked_task_id nullable
- ai_plan_jobs: owner_user_id, plan_id, status(queued/running/succeeded/failed), request_key, attempts, usage, sanitized_error, timestamps
- plan_applications: plan_id, revision, cycle_id, idempotency_key, created_at; unique ตาม plan/revision เพื่อกัน apply ซ้ำ
- ต้นทุนตามแผนไม่บันทึกลง Transaction จนเกิดรายการจริง
- Revision และ application ใช้ transaction + optimistic locking; ไม่ใช้ LLM output เป็น SQL

## API ที่เสนอ
- POST /api/v1/planting-plans: สร้างร่างจาก input ที่ validate แล้ว
- GET /api/v1/planting-plans: owner-filtered pagination
- GET /api/v1/planting-plans/{id}: ร่างปัจจุบัน/สถานะงาน
- PATCH /api/v1/planting-plans/{id}: แก้ร่างพร้อม expectedRevision
- POST /api/v1/planting-plans/{id}/generate: enqueue job, 202 + jobId; idempotency key
- GET /api/v1/ai-plan-jobs/{id}: poll สถานะ ไม่แสดง raw provider error
- POST /api/v1/planting-plans/{id}/apply: expectedRevision + selectedItemIds + create/link cycle; ผู้ใช้ยืนยัน explicit
- POST /api/v1/planting-plans/{id}/archive: เก็บแผน ไม่ลบกิจกรรมจริง
- เริ่ม polling ไม่ใช้ streaming; worker ใช้ job table แบบ durable ไม่ฝากงานสำคัญไว้ใน background task ที่หายเมื่อ restart

## Acceptance scenarios
- ข้าวหนึ่งแปลง: input ครบ → ร่างภาษาไทยพร้อม timeline/สมมติฐาน → ยืนยัน → งานในรอบถูกต้อง
- น้ำไม่พอ/งบจำกัด/ไม่ทราบพันธุ์: ขอข้อมูลเพิ่มหรือแสดงข้อจำกัด ไม่เดาข้อมูล
- AI ล่ม/หมด quota: ไม่เสียร่าง ไม่เกิดงาน และไม่คิด retry แบบไม่จำกัด
- ผู้ใช้ B เปิด/แก้/apply แผนของ A ไม่ได้
- สอง request apply พร้อมกันได้งานชุดเดียว
- Offline: อ่านร่างที่อนุญาตได้ ไม่มีการส่ง prompt/สร้างงานเองเมื่อกลับ online
- จอแคบและฟอนต์ใหญ่ไม่มี overflow; ส่วนหัว/เมนูเดิมไม่ถูกรื้อ
